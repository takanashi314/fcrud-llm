## 3. 決定事項と判断の理由

### 3.1 Epic を「プロジェクト初期化」ではなく「Claude 用の開発ルール」にした

- 計画書のロードマップでは、v0.0 の最初の Epic を「プロジェクト初期化（`feature/project-setup`）」としていた。
- しかし、その Epic には uv の初期化、品質ツール、CI など複数の Task がある。それらがすべて終わるまで `main` にマージされない。
- Claude のクラウドセッションは `main`（デフォルトブランチ）を clone して始まる。そのため、`CLAUDE.md` を早く効かせるには `main` に届ける必要がある。
- そこで、`CLAUDE.md` 用に**小さな Epic を独立させ**、今回のうちに `main` までマージした。Epic の粒度を「main に届けたい単位」で決める、という判断の実例でもある。

### 3.2 `CLAUDE.md` の内容

計画書 `docs/project-plan/01.md` から、毎回守るべきルールだけを抜き出して短くまとめた。詳細は計画書を参照するように書いた。全文を写すと、どちらかの更新漏れで内容が食い違うため。

主な内容:
- **プランが決まったら、許可を待たずに最後まで進める**（止まるのは、範囲外の変更・方針判断・元に戻せない操作のときだけ）
- ブランチ戦略、ブランチを削除しないこと、force-push の禁止
- issue のクローズ運用（`Refs` と `Closes` の使い分け）
- コミットメッセージは英語
- ドキュメントと作業履歴の規約

### 3.3 `.claude/settings.json` の内容

- **allow**: 日常的に使う git コマンド、`uv`、`just`、`docker compose` / `docker build`、`ls`、`mkdir`、GitHub MCP ツール（`mcp__github`）。
- **deny**: 方針に反する操作。force-push、ブランチの削除（ローカル `git branch -d/-D`、リモート `git push origin --delete`）、`git reset --hard`。
  - 「ブランチを削除しない」「force-push 禁止」というルールを、文章だけでなく**設定で強制する**ため。
- 注意: クラウドのセッションでは、ファイルの編集はどのモードでも確認なしで実行される。それ以外の承認ダイアログを減らすには、セッションのモードを **Auto** にするのが確実。

### 3.4 ラベルとマイルストーンを付けていない

- 今回使った GitHub ツールではラベルとマイルストーンを作れなかったため、issue には付けていない。
- 後で作成したときに、#1 と #2 にもさかのぼって付ける。
